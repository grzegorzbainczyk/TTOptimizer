How optimization works

Genetic algorithm, constraints and penalty function

Optimization process

ClassFlow creates many possible timetable solutions and compares them using a penalty function.

Step 1 Input data

Teachers, classes, rooms, subjects, requirements and availability.

Step 2 Validation

The application checks whether the input data is complete enough to start optimization.

Step 3 Population

The optimizer creates a collection of candidate timetables called chromosomes.

Step 4 Evaluation

Every candidate timetable receives a penalty value.

Step 5 Evolution

Selection, crossover and mutation are used to create new timetable generations.

Step 6 Best result

The timetable with the lowest penalty is returned as the optimization result.

What is a penalty?

Penalty is a numeric score describing how many timetable rules or preferences were violated.

i
Lower penalty means a better timetable.

A penalty equal to zero means that the current penalty function did not detect any violations.

Penalty levels

Low 10

A small inconvenience or preference that was not met.

Medium 100

A noticeable issue that reduces timetable quality.

High 1,000

A serious issue that should usually be avoided.

Hard 1,000,000

A conflict that should not occur in a valid timetable.

Example penalty calculation

Violation Count Weight Penalty
Teacher gaps 2 100 200
Late lessons 3 10 30
Room conflict 1 1,000,000 1,000,000
Total penalty 1,000,230

One hard conflict dominates many smaller soft penalties. This ensures that invalid timetables are ranked worse than feasible timetables with minor inconveniences.

Hard and soft constraints

Hard constraints Required rules

Hard constraints represent conflicts that should make a timetable invalid.

  • A teacher cannot teach two lessons at the same time.
  • A class cannot attend two lessons at the same time.
  • A room cannot host two lessons at the same time.
  • Unavailable resources should not be scheduled.
Soft constraints Quality preferences

Soft constraints describe preferences that improve the timetable but do not always make it invalid.

  • Reducing gaps between lessons.
  • Avoiding very late lessons.
  • Using preferred rooms.
  • Distributing lessons more evenly.

How to interpret the result

Penalty = 0 No detected violations

The timetable satisfies all rules currently checked by the penalty function.

Penalty > 0 Some preferences were not met

The timetable may still be usable if it contains only soft violations.

Hard violations Timetable requires correction

The result contains conflicts and should not be treated as final.
